### Task 4 - Watchdog de análise por fork (done)

- **Files:** `.claude/hooks/agent-audit.py` (fork watchdog: `_audited_tool`, `_analysis`, `_apply_outcome`, `_Child`, `_start_child`, `_run_child`, `_fork_available`, `_analyze_in_process`, `MAX_CHILD_MESSAGE`, `CHILD_GRACE_S`; `__main__` flushes and ends with `os._exit(0)`), `.claude/hooks/tests/test_watchdog.py` (new, 26 tests: WD1-WD10, no-zombie, fd-leak, self-destruct, parent-only record), `.claude/hooks/tests/test_hook_process.py` (`WatchdogProcess`: P-HH8 to P-HH11 plus real-process stdout isolation), `.claude/hooks/tests/test_hook_main.py` (`AnalysisLimitAndArming` and `DecisionBeforeRecording` patch `_fork_available` to false)
- **Behavior changes:** the analysis of Bash, Write/Edit/MultiEdit/NotebookEdit and browser/screenshot tools runs in a forked child (other tools, `mode: off` and PreToolUse in `mode: audit` fork nothing; subagent events tag in process under SIGALRM). Protocol over a socketpair (C module `_socket`): line 1 `{"analysis": ...}` or `{"error": name}`, line 2 `{"tags": ...}`; each line capped at 1 MiB; a PreToolUse child waits for a one-byte go before tagging (an addition to the spec, avoids wasted tagging and orphaned git processes); a write whose analysis already carries `in_run` sends no line 2. No line 1 by the deadline: SIGKILL and `analysis_timeout`. EOF, invalid, oversized or wrong-shape line 1: `unclassified_command`, reason `analysis_crash`, categories `["unclassified"]`. `{"error": name}`: the U4 path (`classifier_error`). A dead or late child: record with `in_run: false`, `run_tags: "timeout"`. The child never prints or writes metrics (stdout/stderr replaced, fds 1 and 2 on a closed socket), self-destructs by SIGALRM at limit + 1.0 s, and ends with `os._exit(0)`. The parent's `finally` always kills, closes and polls `waitpid(WNOHANG)` up to 20 ms. `socketpair` or fork failure falls back to in-process SIGALRM.
- **Latency:** fork alone with the old interpreter exit cost +6 ms (copy-on-write teardown at exit); with `os._exit(0)` the hook is faster than the original baseline on every path (Post pytest -5.0 ms, Pre pytest -6.1 ms, Pre deny -4.6 ms, Post Read -7.3 ms; fork alone with the same exit on both sides +2.7 to +4.3 ms). The main session accepted that the fast exit applies to all hook calls (output is flushed first; metrics are appended through raw fds).
