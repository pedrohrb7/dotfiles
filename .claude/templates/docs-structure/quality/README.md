# Quality

Quality snapshots, one file per snapshot. A snapshot records the numbers that measure the project's quality at a point in time: tests per service, coverage, mutation score, front-end audits (e.g. Lighthouse), and whatever other gates the project has.

- File name: `YYYY-MM-DD-topic.md` (date measured, topic naming the delivery it closes - e.g. the plan that was just implemented, or a release).
- Start every new entry from `TEMPLATE.md`.
- **Machine-readable companion:** when the project's quality gate produces a summary file, each snapshot also gets a `YYYY-MM-DD-topic.json` with the same name, generated by a command (never edited by hand). The `.md` is written from it, and a dashboard can be generated from all the `.json` files to show the trend.
- A snapshot is taken when something is delivered: a plan marked as implemented, a release, or - once a pipeline exists - each deploy. It only exists if the project's quality gate passed; a failing gate is fixed, not recorded.
- Numbers come from the generated reports (never typed from memory), and the snapshot says which commit of each service was measured.
- Snapshots are a historical record: never edit an old one. A new measurement is a new file.
- Keep the history table below in sync: one row per snapshot, newest at the bottom, with the headline numbers so the trend reads without opening each file.
