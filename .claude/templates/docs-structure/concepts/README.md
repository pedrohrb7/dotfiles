# Concepts

Evergreen explainers for domain or technical concepts a reader needs to understand the codebase - e.g. `jwt-authentication.md`, `event-sourcing.md`.

- One file per concept, named after the concept (no date prefix - these are updated in place as understanding evolves, not superseded by new dated files).
- No fixed template: write what a new engineer would need to understand the concept before touching related code. Diagrams and examples are welcome where they clarify more than prose.
- If a concept is specific to one decision rather than durable knowledge, it probably belongs in `../specs/` or `../plans/` instead.
