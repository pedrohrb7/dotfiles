# Specs

Design specs written before implementing a non-trivial feature or change, one file per spec.

- File name: `YYYY-MM-DD-topic-design.md` (date written, topic being designed).
- Start every new entry from `TEMPLATE.md`.
- A spec explains *why this design* - the problem, the alternatives considered, and the trade-offs of the chosen approach. The *how and in what order* belongs in a matching file under `../plans/`.
- Keep specs as the historical record of a decision - if the design changes later, add a dated addendum or a new spec rather than rewriting the original.
