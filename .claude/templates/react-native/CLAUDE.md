## Conventions

- Same `components/ui/` vs `components/<feature>/` split as the web frontend: generic reusable primitives vs feature-specific composites.
- Screens stay thin: compose components, delegate logic to a hook or `lib/`.
- `theme/` mirrors the project root's `DESIGN_SYSTEM.md` - never hardcode a one-off spacing/color/type value, extend the token file in both places instead.
- `ios/` and `android/` are generated by the toolchain - route native config changes through `app.config.ts`/config plugins whenever possible. Hand-edits get silently blown away by `prebuild`/`eject` runs.

## Testing

- Unit/component tests colocated with the code they cover.
- `test/e2e/` (Detox/Maestro) on a real simulator/device - gesture, navigation, and platform-specific bugs only surface there, not in component tests.
